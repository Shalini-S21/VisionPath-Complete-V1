1. INTRODUCTION
1.1 Purpose
This document is the Software Requirements Specification (SRS) for VisionPath, an AI-powered personalized career guidance and learning platform. It describes the functional and non-functional requirements, system architecture, data design, and interfaces of the platform for the project team, faculty mentors, and industry reviewers involved in the Full Stack Java (AI-Integrated) Training Programme.
VisionPath helps students understand their skills, interests, personality, and educational background, and uses that information to recommend suitable career paths. Students complete an initial assessment followed by an AI-personalized assessment, receive AI-generated career recommendations, chat with an AI mentor for guidance, generate a personalized study/career roadmap toward a chosen goal, track their progress, receive personalized notifications, and upload a resume to receive an ATS score and improvement recommendations. The platform also provides counsellors with tools to support students and gives administrators oversight of the platform.
1.2 Scope
System Name: VisionPath
What the system does: 
VisionPath is an AI-powered career guidance, assessment, education and career-development platform for students, counsellors, and administrators. It personalizes career assessments, career recommendations, AI mentoring, study/career roadmaps, learning plans, resume/ATS analysis, progress tracking, and notifications. The system's goal is to provide students with a single platform where they can assess themselves, receive personalized career recommendations, understand which skills they need, generate a roadmap toward a selected career, track their progress, and receive AI-based guidance throughout the journey.

2. OVERALL DESCRIPTION
2.1 Product Perspective
VisionPath is a new, self-contained AI-powered career guidance platform built as a set of cooperating microservices behind a single API Gateway. It is not a replacement for an existing institutional system; it is a standalone product aimed at students, counsellors, and administrators who currently lack a single place to combine self-assessment, AI-driven career recommendation, mentoring, roadmap planning, progress tracking, and resume/ATS feedback.
VisionPath addresses the lack of personalized, end-to-end career guidance available to students during important academic and career decision-making stages. Rather than a one-time test, the platform builds a profile of the student's skills, interests, personality, and education, and uses that profile â€” together with an AI-personalized second-stage assessment â€” to recommend relevant careers. Students can then turn a chosen career into an AI-generated study roadmap, track their progress against it, receive contextual notifications, chat with an AI mentor at any stage, and analyze their resume for ATS compatibility. Counsellors support students through the platform, and administrators manage users and platform-level data.

3. SYSTEM ARCHITECTURE
3.1 High-Level Architecture Description
VisionPath follows a layered microservice-based architecture consisting of a React frontend, API Gateway, independent backend microservices, PostgreSQL databases, and an AI integration layer.
The React frontend provides the user interface for Students, Counsellors, and Administrators. Frontend requests are sent to the API Gateway, which performs request routing and works with the authentication mechanism to enforce JWT-based access control.
The API Gateway routes requests to the appropriate backend service, including the Auth Service, Admin Service, Student Service, AI Mentor Service, Assessment Service, Career Service, Counsellor Service, Education Service, Notification Service, Progress Service, Study Plan Service, and Resume Analyzer Service.
The AI Mentor Service receives user messages from the frontend and forwards appropriate requests through the backend AI integration layer to the external AI provider. The AI response is returned to the backend and then delivered to the React frontend.
The Assessment Service manages assessment sessions and responses. Initial assessment information is used to determine the student's areas of interest, skills, education, and other relevant characteristics. The AI integration layer can then generate personalized assessment questions. After completion, assessment results are analyzed to support personalized career recommendations.
The Career Service uses student profile information and assessment results to provide relevant career recommendations and career-related information. Job-related functionality is consolidated within this service rather than being maintained as a separate Jobs Service.
The Study Plan Service manages available study roadmaps and personalized learning plans. Students can search available roadmaps, save a roadmap as an active study roadmap, complete individual tasks, and track roadmap progress. AI can be used to generate personalized roadmaps based on a student's selected career goal and profile.
The Progress Service tracks and presents relevant student progress, including assessment completion, saved careers, active study roadmaps, and learning-task completion.
The Notification Service provides notifications based on relevant student activities, progress, assessment completion, roadmap activity, and other system events.
The Resume Analyzer Service handles resume uploads and resume analysis. It communicates with the appropriate resume parsing/ATS analysis mechanism and provides an ATS-oriented score and recommendations to the student.
The backend services persist their respective information in PostgreSQL, following service ownership and data-isolation principles appropriate to the project's microservice architecture.
For AI-enabled functionality, the backend communicates with the AI Integration Layer, which securely communicates with the external AI provider. The external AI provider's API key is stored on the backend/integration layer and is never exposed to the React frontend.

8. DATABASE DESIGN
8.1 Entity-Relationship Overview
Key relationships:
USERS has a ONE-TO-ONE relationship with STUDENT_PROFILES â€” each student user has one profile.
USERS has a ONE-TO-MANY relationship with ASSESSMENT_RESPONSES â€” one student answers many assessment questions across the initial and personalized stages.
ASSESSMENT_QUESTIONS has a ONE-TO-MANY relationship with ASSESSMENT_RESPONSES â€” one question can be answered by many students.
USERS has a ONE-TO-MANY relationship with CAREER_RECOMMENDATIONS â€” one student can receive multiple AI-generated recommendations.
CAREERS has a ONE-TO-MANY relationship with CAREER_RECOMMENDATIONS â€” one career can be recommended to many students.
USERS has a ONE-TO-MANY relationship with STUDY_ROADMAPS â€” a student can save/generate multiple roadmaps, with one marked active.
STUDY_ROADMAPS has a ONE-TO-MANY relationship with ROADMAP_TASKS â€” one roadmap contains many tasks.
USERS has a ONE-TO-MANY relationship with PROGRESS_RECORDS â€” one student's activity produces an evolving progress record.
USERS has a ONE-TO-MANY relationship with NOTIFICATIONS â€” one student can receive many notifications.
USERS has a ONE-TO-MANY relationship with RESUMES â€” a student can upload multiple resumes over time.
RESUMES has a ONE-TO-ONE relationship with RESUME_ANALYSIS_RESULTS â€” each uploaded resume produces one analysis record.
COUNSELLORS has a MANY-TO-MANY relationship with USERS (students) via COUNSELLOR_STUDENT_MAP â€” one counsellor can support many students, and a student may be supported by more than one counsellor.
