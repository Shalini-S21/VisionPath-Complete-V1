INTRODUCTION 1.1 Purpose This document is the Software Requirements Specification (SRS) for  VisionPath , an AI-powered personalized career guidance and learning platform. It describes the functional and non-functional requirements, system architecture, data design, and interfaces of the platform for the project team, faculty mentors, and industry reviewers involved in the Full Stack Java (AI-Integrated) Training  Programme . VisionPath  helps students understand their skills, interests, personality, and educational background, and uses that information to recommend suitable career paths. Students complete an initial assessment followed by an AI-personalized assessment, receive AI-generated career recommendations, chat with an AI mentor for guidance, generate a personalized study/career roadmap toward a chosen goal, track their progress, receive personalized notifications, and upload a resume to receive an ATS score and improvement recommendations. The platform also provides counsellors with tools to support students and gives administrators oversight of the platform. 1.2 Scope System Name:  VisionPath What the system does:  VisionPath  is an AI-powered career guidance, assessment, education and career-development platform for students, counsellors, and administrators. It personalizes career assessments, career recommendations, AI mentoring, study/career roadmaps, learning plans, resume/ATS analysis, progress tracking, and notifications. The system's goal is to provide students with a single platform where they can assess themselves, receive personalized career recommendations, understand which skills they need, generate a roadmap toward a selected career, track their progress, and receive AI-based guidance throughout the journey. 1.3 Definitions, Acronyms & Abbreviations Term / Acronym Definition SRS System Requirements Specification â€” this document API Application Programming Interface REST Representational State Transfer â€” architectural style for HTTP APIs JWT JSON Web Token â€” used for authentication and authorization ML / AI Machine Learning / Artificial Intelligence LLM Large Language Model â€” powers the AI Mentor, personalized assessment generation, and roadmap generation ATS Applicant Tracking System â€” automated resume-screening software; the Resume Analyzer estimates an ATS-compatibility score CRUD Create, Read, Update, Delete â€” basic data operations CI/CD Continuous Integration / Continuous Deployment â€” automated build and release pipeline FR Functional Requirement NFR Non-Functional Requirement UC Use Case ER Entity-Relationship (database design) Roadmap A structured, ordered set of learning stages, topics, and tasks generated toward a student's chosen career/academic goal 1.4 References Spring Boot Documentation â€” used for backend microservice development and REST API implementation. OVERALL DESCRIPTION 2.1 Product Perspective VisionPath  is a new, self-contained AI-powered career guidance platform built as a set of cooperating microservices behind a single API Gateway. It is not a replacement for an existing institutional system; it is a standalone product aimed at students, counsellors, and administrators who currently lack a single place to combine self-assessment, AI-driven career recommendation, mentoring, roadmap planning, progress tracking, and resume/ATS feedback. VisionPath  addresses the lack of personalized, end-to-end career guidance available to students during important academic and career decision-making stages. Rather than a one-time test, the platform builds a profile of the student's skills, interests, personality, and education, and uses that profile â€” together with an AI-personalized second-stage assessment â€” to recommend relevant careers. Students can then turn a chosen career into an AI-generated study roadmap, track their progress against it, receive contextual notifications, chat with an AI mentor at any stage, and analyze their resume for ATS compatibility. Counsellors support students through the platform, and administrators manage users and platform-level data. 2.2 Product Functions â€” Feature Summary # Feature Name Description 1 Authentication & Role SYSTEM ARCHITECTURE 3.1 High-Level Architecture Description VisionPath  follows a layered  microservice-based architecture  consisting of a React frontend, API Gateway, independent backend microservices, PostgreSQL databases, and an AI integration layer. The  React frontend  provides the user interface for Students, Counsellors, and Administrators. Frontend requests are sent to the  API Gateway , which performs request routing and works with the authentication mechanism to enforce JWT-based access control. The API Gateway routes requests to the appropriate backend service, including the  Auth Service, Admin Service, Student Service, AI Mentor Service, Assessment Service, Career Service, Counsellor Service, Education Service, Notification Service, Progress Service, Study Plan Service, and Resume Analyzer Service . The  AI Mentor Service  receives user messages from the frontend and forwards appropriate requests through the backend AI integration layer to the external AI provider. The AI response is returned to the backend and then delivered to the React frontend. The  Assessment Service  manages assessment sessions and responses. Initial assessment information is used to determine the student's areas of interest, skills, education, and other relevant characteristics. The AI integration layer can then generate personalized assessment questions. After completion, assessment results are analyzed to support personalized career recommendations. The  Career Service  uses student profile information and assessment results to provide relevant career recommendations and career-related information. Job-related functionality is consolidated within this service rather than being maintained as a separate Jobs Service. The  Study Plan Service  manages available study roadmaps and personalized learning plans. Students can search available roadmaps, save a roadmap as an active study roadmap, complete individual tasks, and track roadmap progress. AI can be used to generate personalized roadmaps based on a student's selected career goal and profile. The  Progress Service  tracks and presents relevant student progress, including assessment completion, saved careers, active study roadmaps, and learning-task completion. The  Notification Service  provides notifications based on relevant student activities, progress, assessment completion, roadmap activity, and other system events. The  Resume Analyzer Service  handles resume uploads and resume analysis. It communicates with the appropriate resume parsing/ATS analysis mechanism and provides an ATS-oriented score and recommendations to the student. The backend services persist their respective information in  PostgreSQL , following service ownership and data-isolation principles appropriate to the project's microservice architecture. For AI-enabled functionality, the backend communicates with the  AI Integration Layer , which securely communicates with the external AI provider. The external AI provider's API key is stored on the backend/integration layer and is  never exposed to the React frontend . Impact Mitigation Strategy R01 AI-generated recommendations/questions are irrelevant or low quality on a meaningful share of test cases M H Iterate on prompt design with real assessment data; add a rule-based fallback for low-confidence AI output; validate manually before Internal Review. R02 External AI provider API becomes unavailable, rate-limited, or changes pricing M H Implement the fallback paths defined in Section 6 for each AI module; cache recent responses where reasonable; keep a mock-data layer for development. R03 Resume parsing / ATS analysis mis-extracts content from certain resume formats M M Test against a range of resume templates and file types early; clearly surface extraction failures to the student rather than silently mis-scoring. R04 Training/reference dataset for career and education information is incomplete or not representative M M Curate a reasonably broad career/education reference set; document known gaps; expand iteratively based on mentor feedback. R05 One of the two team members is unable to complete an assigned microservice before a review deadline L H Cross-train both members on the overall architecture in Week 1â€“2; maintain a 1-week buffer in the timeline; daily check-ins to surface blockers early. R06 Docker / docker-compose deployment fails during the live demo due to environment differences M M Test deployment on a clean machine at least a week before the demo; keep a tested docker- compose.yml  as a backup; record a demo video as contingency. R07 Accidental exposure of real personal or resume data in a development environment L H Use synthetic/ anonymised  data in development; never commit real credentials or resumes to Git; use .env files  with . gitignore . R08 Scope creep â€” the team adds features not in this SRS while core functionality remains incomplete M M Freeze scope at Week 1 SRS sign-off; track feature status on GitHub Issues; add new features only in a designated stretch-goal window. R09 AI provider API costs exceed the available budget/quota during heavy testing M M Cache/reuse AI responses during development; rate-limit AI-dependent test runs; monitor usage against provider quota.
